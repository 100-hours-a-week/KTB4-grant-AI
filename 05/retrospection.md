# 회고
## 06-10
한국어 챗봇을 구축하기 위해 생각해야 할 점들이 많이 복잡하고 어려웠다. 아예 Transformer를 from scratch로 만들지, 기존 LLM 모델의 가중치는 가져오지 말고 설계만 가져올지, 아니면 잘 학습된 모델로부터 출발할지 고민해봤다. 다른 사람들이 이미 공개하고 검증된 모델과 가중치 위에서 출발하는 것이 시간과 비용 면에서 좋다고 생각했다. 이후 어떤 백본 위에서 시작할지, 그 기준은 어떻게 설정할지 고민을 많이 했다. EXAONE, Qwen, LLama, Trillion, Bllossom, KANANA 등 여러 후보들 사이에서 일단 어떤 챗봇을 만들까부터 생각을 해봤다. 한국어를 잘 인식하면서 tokenizer도 한국어에 잘 맞고, 범용 목적의 지시를 잘 따르게 하는 것이 일단 가장 중요하다고 생각했다. 어떤 벤치마크들을 통해 평가해야 할 지도 고민했다.
일단 배포용으로도 사용할 수 있으면서 한국어에 맞는 KANANA 위에서 시작하되, Instruct와 Base을 벤치마크에서 평가하자. 그리고 Base를 내가 직접 Instruction tuning해보자.

## 06-11
아니다. 좀 더 큰 목표로 아예 모델 설계부터 처음부터 해서 사전 학습부터 시작하자. 하이브리드 구조(Mamba2/3 + MHA)로! A100 40GB 4장 서버를 고려했을 때 상대적으로 작은 1B 정도의 크기로 하고, Chinchilla law에 따라 사전 학습을 충분히 하기 위해 한국어+영어로 공개된 FineWeb-2을 사용하기로 결정. 한국어에 특화된 EXAONE-4.0 토크나이저를 기준으로 각각 60,874,355와 9,672,101 문서들에서 100,000 개를 샘플링했을 때, 시퀀스의 최대 길이가 2048일 때 각각 92.64%와 90.82%, 4096일 때 98.28%와 97.00%를 커버하고 긴 문서도 일단 토큰이 버려지지 않고 <EOS>로 붙여지니 2048로 가기로 결정. 네트워크 속도 때문에 데이터 공급 방식을 streaming에서 non-streaming 방식으로 바꿔 local 환경에 먼저 다운로드해서 공급하기로 결정.
